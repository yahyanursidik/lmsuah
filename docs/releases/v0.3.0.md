# v0.3.0 — Program Kajian, progres server, revisi dan PDF privat

Tanggal rilis: 20 Oktober 2026. Paket disusun dari main v0.2.2; perbaikan autentikasi, JSON API, loading, jadwal dan konfigurasi Netlify sebelumnya dipertahankan.

## Perubahan

- Workspace Program Kajian mencakup persiapan, seri/kitab, modul, pertemuan multi-materi, timestamp, kuis dan pratinjau.
- Revisi snapshot memakai review independen, konflik versi, histori dan publikasi atomik. Publikasi lama tetap tersedia sampai pengganti disetujui/diterbitkan.
- Progres/enrollment akun nyata disimpan ke server, dengan antrean penyimpanan dan indikator gagal/sukses. Riwayat kuis lama dan percobaan berjalan dapat dibuka tanpa memulai ulang.
- PDF privat di Netlify Blobs memakai sesi/permission, review, versi immutable, inline/range dan kebijakan unduh. PDF approved dapat diterbitkan atomik bersama publikasi pertama program.
- Migrasi 0010–0013 bersifat aditif. Migrator memverifikasi prefix/hash journal dan menjalankan pending DDL+journal dalam satu transaksi, dengan advisory lock dan guard konkurensi.
- CLI baseline dan smoke test copy-only dilengkapi manifest target, pemeriksaan katalog dan fixture rollback.

## Validasi

- Paket rilis terisolasi lulus 281 tes / 44 file, lint 0 error / 0 warning, typecheck/build produksi tanpa warning ukuran bundle, dan bundling 26 fungsi server tanpa error/warning.
- Salinan Neon terverifikasi: baseline 33 tabel cocok dengan 0000–0009; sesudah 0010–0013 menjadi 40 tabel/14 journal/3 trigger aktif tanpa perbedaan katalog atau perubahan COUNT tabel lama.
- Migrasi/perintah baseline diulang: 0 migrasi diterapkan. Uji kegagalan rollback, immutability, review, FK, keunikan progres dan penggantian PDF lulus; tidak ada fixture tertinggal.

## Aktivasi tidak otomatis

Rilis kode **bukan** aktivasi fitur produksi. Tidak ada migrasi saat build/request, perubahan credential, pemetaan role otomatis, atau perubahan environment Netlify oleh paket ini.

1. Verifikasi backup/target dan peroleh persetujuan terpisah untuk merekonsiliasi baseline/migrasi database sumber. Journal sumber masih kosong; jangan mengulang SQL awal.
2. Verifikasi izin least-privilege, dua reviewer berbeda, serta upload/download/range PDF pada Netlify Blobs staging dengan akun nyata.
3. Setelah semua siap, aktifkan flag server `LMS_PROGRAM_REVISIONS_ENABLED=true` dan `LMS_PRIVATE_PDF_ENABLED=true` lalu redeploy. Keduanya default nonaktif dan endpoint tetap memeriksa kelengkapan schema/trigger/izin.

Sebelum fitur diaktifkan, alur lama tetap dipertahankan; UI menampilkan status fitur yang belum tersedia. Sesudah snapshot dipakai, jangan rollback konten dengan mematikan flag: tarik program atau review/terbitkan ulang snapshot lama sebagai revisi baru. Jangan DROP tabel atau menghapus blob/riwayat.
